Why this comparison works—and where the analogy stops

Both sides use identical world rules, rewards, learning rates, exploration and 40-action limits. Ordinary comparison practice rotates evenly through A, B and C. With full or uniform starts, each paired attempt uses the same task, reset and random seed. Adaptive mode lets each side choose its own reset from its own outcomes; task allocation stays round-robin, unlike AlphaNIST’s joint task/reset sampler.

The only memory difference: the shared controller writes to Q[state, action]; separate controllers write to Q[task, state, action]. These tasks differ in starting carry distance, not contact geometry. Identical finishing states therefore share values exactly. This makes positive transfer visible, but does not test the paper’s learned generalization across nuts, gears and connectors. The longer task still has to discover its earlier moves; finishing knowledge alone does not solve it.

THE IDEA, WITHOUT THE MACHINERY

Practice the ending.
Give the beginning
somewhere to lead.

With a reward only at the end, a randomly moving robot may never stumble into success. Useful starting situations make that first reward reachable.

A small analogy, honestly labeled.

AlphaNIST uses PPO, neural networks, detailed simulation, and many assembly tasks. Here, tables of numbers learn discrete peg layouts. The comparison shares matching states explicitly; this single-learner lab lets you inspect reset sampling and delayed credit.

01

Create situations, not instructions.

We know where a completed peg belongs. Place it there, then back it out one unit. Now there is a partly assembled starting state—without a demonstrated action sequence.

OmniReset, which AlphaNIST adapts, uses physical perturbations and grasp sampling. Our toy uses direct geometry and discrete rules.

complete = { at_socket, depth: 2, held: true }
partial  = { ...complete, depth: 1 }
02

Let a successful ending teach one action.

From partial insertion, the robot tries lower and finishes. The reward is 1. That action’s value rises from zero to 0.25.

new = 0 + 0.25 × (1 − 0) = 0.25
03

Let an earlier action borrow that value.

Later, lowering from the socket mouth reaches that useful partial state. The reward is still zero, but the next state has a valuable action. The earlier move can now improve too.

target = 0 + 0.96 × 0.25 = 0.24
new    = 0 + 0.25 × (0.24 − 0) = 0.06

These are illustrative first updates. The live inspector shows the actual values in your run. Repeated updates can spread value back toward reaching and grasping.

SMALL ENOUGH TO READ

The whole learning loop.

Zero third-party libraries.
Rust → WebAssembly → your browser.

// The table starts empty. No answers are supplied.
Q[state, action] = 0

repeat:
  start = sample_reset_bank(success_rates)

  until assembled or time_limit:
    action = explore_or_choose_best(Q, state)
    next   = world.step(state, action)
    reward = 1 if assembled else 0

    future = 0 if assembled else max(Q[next])
    target = reward + 0.96 * future
    Q[state, action] += 0.25 * (target - Q[state, action])
    state = next

  record_outcome_for_this_start()

Three pieces to follow

The world decides what a move does. It contains no learned behavior.

The Q table remembers which actions led toward future reward. This substitutes for the paper’s neural controller.

The reset sampler chooses where to begin the next attempt. Its success history is separate from the Q table.

BEYOND ASSEMBLY

What about a robot learning to walk?

A useful extension would be practice across flat ground, small steps and rough terrain. Shared experience could teach balance and foot placement, while success-guided sampling could favor situations the robot can sometimes—but not always—handle. This is a proposed analogy, not an AlphaNIST result.

Knowing the destination is not enough to generate good walking states. Joint angles, momentum, foot contacts and terrain all matter. Starting upright near the goal may teach only the last step, not how to cross a gap. Terrain curricula, motion references or intermediate rewards can supply additional structure; the assembly paper does not establish that completion reward alone solves bipedal locomotion.

What this example leaves out

Contact forces, camera perception, continuous motion, and learned generalization across different assembly geometries. The original paper also includes movement penalties; this toy uses only the completion reward. Nothing here establishes real-robot performance.
